# Model Card — InsureRisk AI

## Model Purpose

InsureRisk AI estimates an applicant's annual health insurance premium from demographic, financial, lifestyle, medical-history, regional, employment, and insurance-plan features.

The application uses an age-based model selection strategy:

- **Age ≤ 25:** Linear Regression
- **Age > 25:** XGBoost Regressor

## Data

The training workflow uses two applicant datasets:

- Young-applicant dataset: 20,096 records before the documented cleaning/modeling workflow.
- Rest-of-applicant dataset: 29,904 records before the documented cleaning/modeling workflow.

The notebooks document missing-value handling, duplicate checks, invalid dependant values, age filtering, income outlier treatment, categorical encoding, medical-history risk feature engineering, and multicollinearity analysis.

## Feature Engineering

Medical history is converted into a normalized risk-score feature using predefined condition weights.

Insurance plans are encoded as:

- Bronze → 1
- Silver → 2
- Gold → 3

Categorical variables are one-hot encoded.

## Intended Use

- Educational ML demonstration
- Portfolio project
- Applicant-level premium estimation prototype
- Demonstration of explainable regression

## Out-of-Scope Use

This model should not be used as:

- A medical diagnostic system
- A standalone insurance underwriting decision maker
- A substitute for actuarial analysis
- A guaranteed insurance pricing system

## Limitations

- Model quality is dependent on the training dataset.
- The medical-history score is an engineered feature based on predefined weights.
- Model explanations describe learned model behavior, not causation.
- Fairness and regulatory suitability require dedicated validation.
- The training notebooks should be rerun to regenerate metrics whenever the data, feature engineering, or model configuration changes.

## Fairness & Responsible Use

Features such as gender, region, marital status, and health-related information may have fairness and regulatory implications in real insurance applications. This portfolio project should therefore be treated as a technical demonstration rather than a production underwriting model.
